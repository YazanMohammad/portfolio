# Portfolio V2: shared contract

Spec: `docs/superpowers/specs/2026-11-25-portfolio-v2-redesign-design.md`

This file fixes the names, shapes, paths and limits that the backend, admin and public-site plans
all rely on. Plans may add private helpers but must not rename or reshape anything here. A change to
this file needs the owner's (Opus) sign-off.

## 1. Layout (flat, one package)

The repo is flattened into one package by **Task 0** (section 10), which runs before every other
task. There are no workspace packages and no `@workspace/*` imports.

| Path | Owner plan | Holds |

| `shared/` | backend | Zod schemas and types (`shared/schemas.ts`, `shared/types.ts`, `shared/index.ts`) used by frontend and server |
| `db/` | backend | Drizzle schema `db/schema.ts`, client `db/client.ts`, migrations `db/migrations/`, seed `db/seed.ts` + `db/seed-data.ts`; `drizzle.config.ts` at the root |
| `server/` | backend | HTTP helpers, auth, sessions, rate limits, origin check, Blobs, cache purge |

**Scripts** (root `package.json`): `dev` (`netlify dev`), `dev:web` (`vite`), `build`
(`tsc --noEmit && vite build`), `typecheck`, `test` (Vitest, all projects), `test:api`,

**Tests:** one root `vitest.config.ts` with two projects: `node` (`server/**`, `db/**`, `shared/**`,
`netlify/**`, `tests/api/**`, `vite-plugins/**` and `src/lib/api.test.ts`) and `dom` (jsdom,
`src/**/*.test.{ts,tsx}` except `src/lib/api.test.ts`, setup file `src/test/setup.ts`). Backend Task 1 creates it; the other plans only add test files and setup.

## 3. Data shapes (JSON, camelCase; dates as strings)

`YearMonth` = `"YYYY-MM"`. `IsoDateTime` = ISO 8601 string. `Url` = absolute `http:`/`https:` URL.
`FileKey` = string returned by an upload. Nullable means the fact is unknown or not set; the public
page hides it.

```ts
type Profile = {
  name: string;               // 1..100
  headline: string;           // 1..80, e.g. "AI Engineer"
  intro: string;              // 1..200, hero line
  about: string;              // 0..3000, plain text with blank-line paragraphs
  location: string | null;    // ..100
  email: string;              // email, ..200
  githubUrl: Url | null;
  linkedinUrl: Url | null;
  available: boolean;
  availabilityText: string | null; // ..120
  photoKey: FileKey | null;
  photoAlt: string | null;    // ..200, required when photoKey is set
  cvKey: FileKey | null;
  updatedAt: IsoDateTime;
};

type Project = {
  id: number;
  slug: string;               // ^[a-z0-9]+(-[a-z0-9]+)*$, 1..80, unique
  title: string;              // 1..100
  summary: string;            // 1..200
  body: string;               // Markdown, 0..20000
  role: string | null;        // ..200
  category: string;           // 1..50
  technologies: string[];     // each 1..40, max 20
  liveUrl: Url | null;
  githubUrl: Url | null;
  imageKey: FileKey | null;
  imageAlt: string | null;    // ..200, required when imageKey is set
  featured: boolean;
  isVisible: boolean;
  sortOrder: number;
};
type ProjectCard = Omit<Project, "body" | "isVisible">;

type Experience = {
  id: number;
  position: string;           // 1..100
  company: string | null;     // ..100
  location: string | null;    // ..100
  startDate: YearMonth | null;
  endDate: YearMonth | null;  // must be null when current
  current: boolean;
  bullets: string[];          // each 1..300, max 10
  isVisible: boolean;
  sortOrder: number;
};

type Education = {
  id: number;
  degree: string;             // 1..100
  school: string;             // 1..100
  location: string | null;
  startDate: YearMonth | null;
  endDate: YearMonth | null;
  description: string | null; // ..1000
  isVisible: boolean;
  sortOrder: number;
};

type Skill = {
  id: number;
  name: string;               // 1..50
  category: string;           // 1..50, e.g. "Languages", "AI", "Frameworks", "Tools"
  iconSlug: string | null;    // ..50, name of a real tool icon, e.g. "python"
  isVisible: boolean;
  sortOrder: number;
};

type Message = {
  id: number;
  name: string;
  email: string;
  subject: string | null;
  message: string;
  isRead: boolean;
  archivedAt: IsoDateTime | null;
  createdAt: IsoDateTime;
};

type PublicContent = {
  profile: Omit<Profile, "cvKey" | "photoKey"> & { photoUrl: string | null; cvUrl: "/cv" | null };
  projects: ProjectCard[];    // visible only, featured first, then sortOrder
  experience: Omit<Experience, "isVisible">[];  // visible only, current first, then sortOrder
  education: Omit<Education, "isVisible">[];
  skills: Omit<Skill, "isVisible">[];
  settings?: { copy: SiteCopy; theme: SiteTheme }; // API always includes this; optional for older snapshots
};
type PublicProject = Omit<Project, "isVisible"> & { imageUrl: string | null };

type FillInItem = { section: "profile" | "projects" | "experience" | "education"; id: number | null; field: string; label: string };
type AdminSummary = {
  unreadCount: number;
  recentMessages: Message[];  // newest 3 unread, else newest 3
  counts: { projects: number; experience: number; education: number; skills: number; messages: number };
  toFillIn: FillInItem[];
  lastSavedAt: IsoDateTime | null;
};
type UploadResult = { key: FileKey; url: string; contentType: string; size: number };
```

Zod schemas in `shared/schemas.ts` (inputs omit `id`, `updatedAt`, `createdAt`):
`ProfileInput`, `ProjectInput`, `ExperienceInput`, `EducationInput`, `SkillInput`,
`ReorderInput = { ids: number[] }` (non-empty, unique, ≤200),
`MessageInput = { name ..100, email ..200, subject? ..150, message 1..5000, website: "" }`
(`website` is the honeypot; any non-empty value is rejected),
`MessagePatch = { isRead?: boolean; archived?: boolean }` (at least one key),
`LoginInput = { password: string 1..200 }`.
Updates use the full input schema (PUT replaces), not partials. Export each type as `z.infer`.

## 4. Routes

Function files in `netlify/functions/`. Paths use Netlify `config.path`. Every admin route calls
`requireAdmin(req)` first; every non-GET route calls `checkOrigin(req)` first.

| File | Method | Path | Body → Response |
|---|---|---|---|
| `content.ts` | GET | `/api/content` | → `PublicContent` (cache tag `content`) |
| `project.ts` | GET | `/api/projects/:slug` | → `PublicProject` (tags `content`, `project:<slug>`) |
| `messages.ts` | POST | `/api/messages` | `MessageInput` → 201 `{ ok: true }` |
| `files.ts` | GET | `/api/files/:key` | → file bytes, `Cache-Control: public, max-age=31536000, immutable`, `X-Content-Type-Options: nosniff` |
| `cv.ts` | GET | `/cv` | → 302 to `/api/files/<cvKey>`, 404 if none |
| `auth-login.ts` | POST | `/api/auth/login` | `LoginInput` → 204 + `Set-Cookie` |
| `auth-logout.ts` | POST | `/api/auth/logout` | → 204, clears cookie |
| `auth-me.ts` | GET | `/api/auth/me` | → 200 `{ authenticated: true }` or 401 |
| `admin-summary.ts` | GET | `/api/admin/summary` | → `AdminSummary` |
| `admin-profile.ts` | GET, PUT | `/api/admin/profile` | `ProfileInput` → `Profile` |
| `admin-settings.ts` | GET, PUT | `/api/admin/settings` | `SettingsInput` → `AdminSettings` (section 11) |
| `admin-collection.ts` | GET, POST | `/api/admin/:collection` | `XInput` → `X[]` / 201 `X` |
| `admin-collection.ts` | PUT, DELETE | `/api/admin/:collection/:id` | `XInput` → `X` / 204 |
| `admin-collection.ts` | PUT | `/api/admin/:collection/order` | `ReorderInput` → 204 |
| `admin-messages.ts` | GET | `/api/admin/messages?status=unread\|all\|archived` | → `Message[]` newest first |
| `admin-messages.ts` | PATCH, DELETE | `/api/admin/messages/:id` | `MessagePatch` → `Message` / 204 |
| `admin-files.ts` | POST | `/api/admin/files?kind=image\|cv` | multipart field `file` → 201 `UploadResult` |

`:collection` ∈ `projects | experience | education | skills`; anything else → 404.
Admin GET lists return all rows (hidden included) by `sortOrder`. Every admin write purges tag
`content` (and `project:<slug>` for old and new slugs on project writes) and sets `lastSavedAt`.

Cookie: `__Host-session=<base64url 32 random bytes>; HttpOnly; Secure; SameSite=Strict; Path=/;
Max-Age=604800`. Sessions renew on use. Under `netlify dev` on http, `Secure`/`__Host-` cannot work:
use cookie name `session` without `Secure` only when `SITE_ORIGIN` starts with `http://localhost`.

Limits: login: 5 failures per IP hash per 15 min → 429 for 15 min; failed login answers after a
fixed 500 ms. Messages: 3 per IP hash per hour → 429. Uploads: `image` = JPEG/PNG/WebP ≤4 MB,
`cv` = PDF ≤4 MB (see §9.1), type from magic bytes; else 415 / 413. Uploading `kind=cv` does not change the
profile by itself; the admin saves `cvKey` through `PUT /api/admin/profile`. Replaced or removed
files are NOT deleted from Blobs by any save or delete (same for `photoKey` and project `imageKey`).
(Amended after backend Task 12 review: two overlapping saves could delete a file the current profile
still points to. Leaving unused files costs a little storage; no file is ever lost.)

## 5. Errors

Every non-2xx JSON response:

```ts
type ApiError = { error: { code: ErrorCode; message: string; fields?: Record<string, string> } };
type ErrorCode = "validation" | "unauthorized" | "forbidden_origin" | "not_found" | "conflict"
  | "too_large" | "unsupported_type" | "rate_limited" | "server";
```

Status: validation 400 (with `fields` keyed by input path, e.g. `"bullets.2"`), unauthorized 401,
forbidden_origin 403, not_found 404, conflict 409 (duplicate slug), too_large 413,
unsupported_type 415, rate_limited 429 (with `Retry-After` seconds), server 500 (no internals in
`message`).

## 9. Integration decisions (these override the three plans where they differ)

1. **Upload limits:** Netlify rejects function request bodies over about 6 MB. Both kinds are capped
   at **4 MB**: `image` (JPEG/PNG/WebP) ≤ 4 MB and `cv` (PDF) ≤ 4 MB. Server returns 413; the admin
   checks size before sending and also handles a 413 whose body is not JSON.
2. **Session cookie:** name `__Host-session`; value is 32 random bytes encoded as base64url;
   attributes `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/`, `Max-Age=604800`. The database
   stores the SHA-256 of the value, never the value. Local http dev: name `session`, no `Secure`.
3. **Check order on admin writes:** `checkOrigin` first, then `requireAdmin`. A foreign origin gets
   403 even without a session. Admin GETs only call `requireAdmin`.
4. **Extra storage the backend plan added (accepted):** a `site_state` table for `lastSavedAt`;
   `profile.photo_alt` and `skills.icon_slug` columns; the message rate limit as one atomic
   `INSERT ... SELECT ... WHERE count < 3`.
5. **`ApiRequestError`:** constructor `new ApiRequestError(message: string, status: number,
   code: ErrorCode, fields?: Record<string, string>, retryAfter?: number)`; `retryAfter` (seconds)
   is read from the `Retry-After` header. `shared/` also exports the response types
   `Profile, Project, ProjectCard, Experience, Education, Skill, Message, PublicContent,
   PublicProject, AdminSummary, FillInItem, UploadResult, ApiError, ErrorCode`.
6. **File ownership for shared config** (flat layout, section 1):
   - `vite.config.ts`: Task 0 moves it to the root with the aliases; **public-site Task 1** removes
     the PORT/BASE_PATH checks (defaults 5173 and `/`) and the Replit plugins. Backend does not edit it.
   - `vitest.config.ts` (root, both projects) : **backend Task 1**. Public-site Task 1 creates only
     `src/test/setup.ts`; admin Task 1 adds `src/test/render.tsx` and `playwright.config.ts`.
   - `src/index.css`: public-site Task 3 owns the `SITE TOKENS` block (kit names). The **admin plan
     owns the `@theme inline` block and the shadcn variables**: in its visual task it points them at
     the kit tokens (e.g. `--background: var(--p-bg)`) and changes `@theme` from
     `hsl(var(--x))` to `var(--x)`, so both sides share one palette.
7. **Kit CSS on admin routes:** the kit's `<link data-kit>` tags live in `index.html`. `AdminLayout`
   and the login page call `setKitEnabled(false)` from `src/lib/site/kit.ts` on mount, so `.btn`,
   `.card`, `.nav`, `.wrap` from the kit never style the admin. Admin markup must not use kit class
   names.
8. **Fonts:** self-hosted under `public/fonts/` (public-site Task 3 downloads the
   dealt pairing's WOFF2 files). The CSP stays `'self'` for fonts, styles and scripts; no Google
   Fonts link anywhere.
9. **Seed copy and icons:** `db/seed-data.ts` imports `PROFILE_INTRO` and `PROFILE_ABOUT`
   from `src/content/copy.ts` (public-site Task 2 writes it). Skill `iconSlug`
   values: TypeScript `typescript`, JavaScript `javascript`, Python `python`, Java `java`, C# `csharp`,
   C++ `cplusplus`, C `null`, PHP `php`, SQL `null`, React `react`, ASP.NET Core `dotnet`, Git `git`,
   EF Core `null`, LLMs `null`. (Amended in public-site Task 8: no plain C icon exists, and the
   SQL skill is SQL Server, so the PostgreSQL logo would be wrong.)
10. **Routes:** `App.tsx` (admin plan) also maps the fallthrough to `@/pages/site/NotFound`. The
    public site's Contact lives in the dealt close (`footer.closing#contact`); nav links to `#contact`.
11. **Extra env vars:** `DATABASE_URL_TEST` and `DATABASE_URL_TEST_UNPOOLED` (Neon test branch, local

## 11. Editable site settings (November 26, 2026)

This user-approved extension supersedes the initial seven-colour editor: background is fixed at
`#0c0c0c`; Look exposes one Tone slider, not colour inputs.

**Storage:** `site_settings` is a singleton (`id integer PRIMARY KEY DEFAULT 1`, CHECK `id = 1`),
with non-null `copy jsonb DEFAULT '{}'`, `theme jsonb DEFAULT '{}'`, and non-null
`updated_at timestamptz DEFAULT now()`. Migration `0001_familiar_titania.sql` only creates this
table; no existing table/data changes. No seed row is required. Plain seed checks this table;
`--force` clears it alongside the other content tables, without touching messages or sessions.
Apply migrations to TEST only with `pnpm db:migrate:test`; run DB suites only with `pnpm test:db`.

**Copy:** `SiteCopy` is the nested string shape exported as `siteCopy` from
`src/content/copy.ts`. `CopyOverrides` is generated recursively from that shape; every branch
is strict on writes, every leaf optional, trimmed and at most 300 characters. Leaves named
`lead`, `sent`, `networkError`, `rateLimited`, `line`, `loadError`, or `description` allow 1000.
An empty string uses the bundled default. Copy is plain text, never HTML/CSS. Existing profile,
project, experience, education and skill text remains in its existing editing pages.

```ts
type SiteTheme = {
  hue: number; // integer 0..359; default 73 (original accent hue is about 73.10 degrees)
  grid: boolean; sphere: boolean; sectionShapes: boolean; marquee: boolean;
  cursorPreview: boolean; nameReveal: boolean; // all default true
  heroShape: "sphere" | "ring" | "halfDisc"; // default sphere
  highlightWord: string; // trimmed, max 40, default Jordan; empty disables highlighting
};
type SettingsInput = { copy?: DeepPartial<SiteCopy>; theme?: Partial<SiteTheme> };
type AdminSettings = {
  copy: DeepPartial<SiteCopy>; theme: Partial<SiteTheme>;
  defaults: { copy: SiteCopy; theme: SiteTheme };
  updatedAt: IsoDateTime | null;
};
```

Only `hue`, the six toggles, `heroShape`, and `highlightWord` are accepted in theme writes.
No client hex/CSS values are accepted or persisted. `shared/palette.ts` derives lowercase,
six-digit hex colours for bg, surface, line, text, muted, accent and onAccent. It lightly tints
neutrals, raises vivid accent lightness as needed, and chooses the higher-contrast dark onAccent.
Tests enumerate every integer hue and require all five pairs to reach 4.5:1: text/bg, muted/bg,
text/surface, onAccent/accent, accent/bg. The admin uses this same function for its preview strip
(accent, muted text, grid sample and dither swatch) and contrast readouts.

**API:** GET `/api/admin/settings` returns stored overrides plus defaults, including empty
overrides and null updatedAt when no row exists. PUT validates the body, replaces each provided
branch in full and preserves an omitted branch; `{copy:{}}` or `{theme:{}}` resets that branch.
It upserts id 1, updates updatedAt, atomically touches lastSavedAt through the existing helper,
and purges tag content after the successful write. Both branches are optional; unknown keys
or invalid leaves return 400 with dotted field paths. `adminHandler` enforces 401 and origin-first
403 before database work, as for profile. Function config.path is the literal
`"/api/admin/settings"`. There are now 30 method/path entries in the admin route test table.

GET `/api/content` always includes merged `settings: {copy, theme}`. The shared merge helper
traverses only known default keys, discards unknown/invalid stored leaves, uses defaults for empty
copy leaves and safely handles missing rows and future keys. The client merges again over bundled
defaults for older API responses and the static fallback snapshot; no unsafe JSON becomes CSS.
`.site-shell` uses a fixed property allowlist populated exclusively from derived palette output.
The static head transform uses snapshot copy for title, descriptions, skip link and hero actions.

**Public behaviour:** toggles omit the grid, hero canvas, section canvases, marquee, cursor
preview or letter reveal. With marquee off the accessible static skills list remains. Disabling
cursor preview restores the in-flow project plate. Hero shape selects sphere, ring or half disc;
