# Admin Dashboard Implementation Plan

> **Integration:** contract section 9 (`docs/superpowers/plans/2026-11-25-contract.md`) overrides this plan where they differ.


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the localStorage admin with a real admin UI that edits the live site through the API: login, dashboard, profile, four list editors and a message inbox.

**Architecture:** Every page talks to the backend only through `src/lib/api.ts` (contract section 6) and the TanStack Query keys in the contract. One generic list editor (`ListEditor`) is configured per collection; one set of form field components shows client Zod errors and server `fields` errors in the same place. Unsaved-changes handling and Ctrl/Cmd+S live in one small module used by every form.

**Tech Stack:** React 19, wouter, TanStack Query, react-hook-form + `@hookform/resolvers` (zod), `@shared` (frontend alias for `shared/`), shadcn/Radix (Sheet, AlertDialog, Switch, Select), sonner, `@dnd-kit/core` + `@dnd-kit/sortable` + `@dnd-kit/utilities`, `react-markdown` + `remark-gfm`, Vitest + Testing Library + jsdom, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-25-portfolio-v2-redesign-design.md` (sections 2, 4, 12, 13). Binding names: `docs/superpowers/plans/2026-11-25-contract.md` (sections 1, 3, 5, 6, 7, 9, 10). Layout is flat (section 1): one package, frontend in `src/`, aliases `@/*` and `@shared/*`.

- Own only `src/pages/admin/*`, `src/components/admin/*`, `src/lib/admin/*`, `src/components/ui/*`, `src/test/render.tsx`, `playwright.config.ts`, `e2e/*`, `src/App.tsx`, and the `@theme inline` block and shadcn variables in `src/index.css` (contract 9.6). - Use only contract names: `apiGet`, `apiSend`, `apiUpload`, `fileUrl`, `ApiRequestError`, the `*Input` schemas and the types in contract section 3, and the query keys in section 6. Do not re-declare them.
- Drag and drop: `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities`. Markdown: `react-markdown` + `remark-gfm`. **No `rehype-raw`, no `dangerouslySetInnerHTML`.** Test tools: `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `@playwright/test`. Install the newest release the 1-day `minimumReleaseAge` allows; never disable that rule or add `minimumReleaseAgeExclude` entries.
- Visual: same tokens and fonts as the public site. Use Tailwind token classes (`bg-background`, `text-foreground`, `border-border`, `text-muted-foreground`, `font-sans`) and never hard-coded colours, so the public plan's `src/index.css` variables apply without edits. No gradients, glows, text gradients, violet, or animated backdrops. Denser than the public site: 14px body, `h-9` controls, 8px spacing steps.
- Copy: plain, short, no jargon, no exclamation marks. Buttons say what they do ("Save", "Delete project").
- Accessibility: every control has a visible label (not placeholder-only); errors use `aria-invalid` + `aria-describedby`; focus ring is never removed; all actions work by keyboard.
- The server is the authority. The UI never assumes a write worked: update the screen from the response or refetch, show a toast only after success.
- Tests mock `@/lib/api` with `vi.mock`; they never hit the network. Only the Playwright smoke needs the backend (`netlify dev`).
- Commands run from the repo root with the root scripts (`pnpm test`, `pnpm typecheck`, `pnpm build`, `pnpm e2e`); no `--filter`. Frontend files import with `@/*` and `@shared/*`. Commit after each task on branch `redesign-v2`.

## Review Focus

Failure modes the spec implies that are easy to miss (each has a test in the named task):

1. **Session ends while editing** (7-day cookie, or logout in another tab): a 401 on any call must send the user to login with a message, not leave a form that silently fails. Task 3.
2. **Double save** (double-click, or Ctrl+S held down): only one request goes out while one is pending. Task 6.
3. **Bad upload** (wrong type, over 4 MB image / 4 MB CV, server 413/415): checked before sending where possible; the server message appears under the drop zone; the form keeps its previous image. Task 7.
4. **Hostile Markdown** (`<script>`, `<img onerror>`, `javascript:` links, in a project write-up): shown as inert text or a plain non-link, in the preview. Task 7.
5. **Awkward message content** (subject with `&`, `#`, non-ASCII, or empty subject; HTML in the body; empty inbox): `mailto:` is correctly encoded, text is never rendered as HTML, and empty states have copy. Task 13.

Also pinned: duplicate slug (409) lands under the slug field (Task 9); the login slow-down text when `Retry-After` is missing (Task 4).
