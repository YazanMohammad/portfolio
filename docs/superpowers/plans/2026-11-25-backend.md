# Portfolio V2 Backend Implementation Plan

> **Integration:** contract section 9 (`docs/superpowers/plans/2026-11-25-contract.md`) overrides this plan where they differ.
>
> **Run order:** contract section 10 (Task 0, flatten the repo into one package) must be done before Task 1. This plan uses the flat layout of contract section 1: no workspace packages, no `@workspace/*` imports; code in `server/`, `db/`, `netlify/` and `tests/` uses relative imports.


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the database, shared Zod schemas, server library, Netlify Functions, frontend fetch helper, build config and tests that the admin and public-site plans rely on.

**Architecture:** `db/` holds the Drizzle schema (`db/schema.ts`) and a Neon HTTP client (`db/client.ts`). `shared/` holds hand-written Zod schemas and types (no server code, so the browser can import it). `server/` holds all server logic (errors, auth, rate limits, files, cache). Each file in `netlify/functions/` is a thin handler that calls `server/`. Tests call handlers directly with a `Request`, against a Neon test branch; Blobs and cache purge are mocked. One root `package.json` holds all dependencies and scripts.

**Tech Stack:** Neon (`@neondatabase/serverless`, `drizzle-orm/neon-http`, `drizzle-kit`), Netlify Functions (`@netlify/functions`), Netlify Blobs (`@netlify/blobs`), Zod 3, Vitest, `tsx`, `netlify-cli` (dev only), Node 22.

**Spec:** `docs/superpowers/specs/2026-11-25-portfolio-v2-redesign-design.md` (sections 7-10, 13-16). **Contract (binding, do not rename or reshape):** `docs/superpowers/plans/2026-11-25-contract.md`. Section numbers below ("contract §4") refer to it.

## Global Constraints

- `pnpm-workspace.yaml` `minimumReleaseAge: 1440` stays. Only well-established packages. No new package unless named in this plan.
- Secrets only in env vars: `DATABASE_URL`, `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, `SITE_ORIGIN` (contract §2). Local only: `DATABASE_URL_UNPOOLED`, `DATABASE_URL_TEST`, `DATABASE_URL_TEST_UNPOOLED`, `BLOBS_SITE_ID`, `BLOBS_TOKEN` (seed only). `.env` stays git-ignored; commit `.env.example` with names only.
- No `drizzle-kit push`. Migrations are `drizzle-kit generate` into `db/migrations/`, applied by `drizzle-kit migrate` on the unpooled URL.
- Password: scrypt from `node:crypto`, format `scrypt$16384$8$1$<salt b64>$<hash b64>`, 16-byte salt, 64-byte key, constant-time compare. No extra dependency.
- Session cookie `__Host-session`, `HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=604800`; token = 32 random bytes, base64url. Local-http exception: name `session`, no `Secure`, only when `SITE_ORIGIN` starts with `http://localhost`.
- Login: 5 failures per IP hash per 15 min, then 429 for 15 min. Failed login answers after a fixed 500 ms. Messages: 3 per IP hash per hour. IP hash = HMAC-SHA256 keyed with `SESSION_SECRET`; raw IPs are never stored or logged.
- Message limits: name 100, email 200, subject 150, message 5000; honeypot field `website` must be `""`.
- Uploads (admin only): image JPEG/PNG/WebP ≤ 4 MB, `cv` PDF ≤ 4 MB (contract §9.1); type from magic bytes, never the name or declared type; no SVG; random key; served with `X-Content-Type-Options: nosniff` and `Cache-Control: public, max-age=31536000, immutable`.
- Every admin function: non-GET → `checkOrigin` first, then `requireAdmin`. Errors use the contract §5 shape and status table. No internals in 500 messages.
- Public cache: `Netlify-CDN-Cache-Control: public, max-age=60, stale-while-revalidate=300, durable` plus `Netlify-Cache-Tag`; browser `Cache-Control: public, max-age=0, must-revalidate`. Admin writes purge tags; a failed purge is logged and ignored.
- Neon HTTP driver only; use `db.batch()` for multi-statement writes.
- User preference: plain, short language in code comments, messages and docs.

## Review Focus

Input classes the spec implies but does not spell out. Each has a test in the task named.

1. Request with no client IP (local dev, odd proxy): must hash a fixed fallback bucket, still be rate limited, never throw. (Task 7)
2. Upload with a lying name or `Content-Type` (PDF named `.png`, SVG, empty file, no `file` field): 415 or 400, never stored. (Task 9, Task 14)
3. Malformed body (invalid JSON, wrong content type, array instead of object): 400 `validation`, never 500. (Task 5, Task 11)
4. Garbage, expired or unknown session cookie: 401, never 500; expired rows are not accepted. (Task 8)
5. Hidden project (`isVisible=false`) or renamed slug: 404 from `/api/projects/:slug`, absent from `/api/content`; duplicate slug on create or rename: 409. (Task 10, Task 13)

### Task 7: IP hashing and rate limits

Model: OPUS (security)

**Files:**
- Create: `server/ip.ts`, `rate-limit.ts`, `ip.test.ts`; `tests/api/rate-limit.test.ts`
- Modify: `server/index.ts`

**Interfaces:**
- `ip.ts`: `clientIp(req: Request, ctx?: { ip?: string }): string | null` (prefers `ctx.ip`, then `x-nf-client-connection-ip`; ignores `x-forwarded-for`, which a client can set); `hashIp(ip: string | null): string` → HMAC-SHA256 hex keyed with `SESSION_SECRET`; `null` hashes the fixed string `"unknown"`. Throws if `SESSION_SECRET` is shorter than 32 bytes after base64 decode.
- `rate-limit.ts` (all take optional `now: Date = new Date()` so tests can move time):
  - `checkLoginAllowed(ipHash: string, now?): Promise<{ allowed: true } | { allowed: false; retryAfter: number }>`: counts `login_attempts` rows with `success=false` in the last 15 min; at 5 or more, `retryAfter` = seconds until the oldest of those 5 leaves the window (min 1).
  - `recordLoginAttempt(ipHash: string, success: boolean, now?): Promise<void>`; a success also deletes that hash's failure rows. Opportunistically deletes rows older than 1 day.
  - `insertMessageIfAllowed(ipHash: string, input: MessageInput, now?): Promise<boolean>`: one SQL statement `INSERT ... SELECT ... WHERE (SELECT count(*) FROM messages WHERE ip_hash = $1 AND created_at > now - 1 hour) < 3 RETURNING id`; returns whether a row was inserted. One statement keeps check and insert atomic on the HTTP driver.
